# Building and testing

Prerequisites, commands, and the Go parser's separate toolchain.
See [Verification.md](Verification.md) for how to know a change actually works.

## Prerequisites
- Java 25+ (shell and MCP modules: `shell-core`, `jfr-shell`, `jfr-mcp`, `hdump-shell`, `pprof-shell`, `otlp-shell`)
- Java 8+ (parser and tools modules: `parser-core`, `tools`, `demo`)
- Test recordings are **generated by the build** (`test-recordings` module, see its README): every test
  task depends on `:test-recordings:generateTestRecordings`, which writes `test-ap.jfr`, `test-jfr.jfr`
  and `test-dd.jfr` where the suites read them. CI never downloads them.
- The real recordings are optional: `./get_resources.sh` downloads them from Dropbox and replaces the
  generated files (each carries a `.generated` marker); the generator then keeps them.
  - It accepts a file only if it starts with the JFR magic `FLR\0` — downloaded, already present or
    restored from a CI cache — and replaces one that does not. It attempts every recording, then exits
    non-zero naming each one it could not obtain, with the page title when the host answered with HTML.
  - To use a mirror, set `JAFAR_TEST_AP_URL`, `JAFAR_TEST_JFR_URL` or `JAFAR_TEST_DD_URL` (any URL curl
    accepts, `file://` included).
  - CI does not run this script: it tests against the generated recordings. The repository variable
    `JAFAR_TEST_DD_URL` that CI used to pass to it (#140) is no longer read by any workflow.

## Essential Commands
```bash
# Build all modules (generates the test recordings first)
./gradlew build

# Optional: replace the generated test recordings with the real ones
./get_resources.sh

# A large recording for benchmarks (about 1.1 GB at 400 chunks, ~12 min)
./gradlew :test-recordings:generateBenchmarkRecording -Pchunks=400 -Poutput=/tmp/large.jfr

# Build shadow JARs for all modules
./gradlew shadowJar

# Run tests
./gradlew test

# Run tests with verbose output
./gradlew test --info

# Run a specific test class
./gradlew :parser-codegen:test --tests "io.jafar.parser.TypedJafarParserTest"

# Run demo application
java -jar demo/build/libs/demo-all.jar [jafar|jmc|jfr|jfr-stream] /path/to/recording.jfr

# Run JFR Shell (Interactive JFR Analysis)
./gradlew :jfr-shell:run --console=plain

# Rebuild the gradle plugin
./rebuild_plugin.sh

# Code formatting (Spotless)
./gradlew spotlessApply

# Check formatting
./gradlew spotlessCheck

# Publish to local Maven repository
./gradlew publishToMavenLocal
```

## Go parser Commands
The `go-parser/` directory is a standalone Go module and is deliberately kept out of the Gradle
build; `./gradlew build` neither builds nor tests it.

```bash
cd go-parser
go test ./...            # unit tests plus the JFR recordings checked into the repo
go test -bench . ./...   # throughput benchmarks
go vet ./...
gofmt -l .               # must print nothing
```

Only the untyped parser is ported. The typed API depends on run-time bytecode generation for
interfaces discovered at run time and has no Go equivalent - do not attempt to port it.

The Go and Java untyped parsers must be kept at parity - see the parity rule under **Rules** below
before changing either of them.
Benchmarks need a large recording. The **Go Parser Benchmarks** workflow
(`.github/workflows/go-parser-bench.yml`) generates one (about 1.1 GB, 400 chunks) with
`:test-recordings:generateBenchmarkRecording` and points `JAFAR_BENCH_JFR` at it. It runs on demand (`workflow_dispatch`, with inputs for benchtime, count,
benchmark pattern and an optional baseline ref to diff against via benchstat), weekly, and on pushes
to `main` that touch `go-parser/`. It runs the correctness tests against the generated recordings
before benchmarking, and publishes the numbers to the job summary plus an artifact. Do not add the
large recording to the fast per-PR job; it would slow every PR for numbers that are too noisy to gate
on. Locally, `./get_resources.sh` plus `JAFAR_BENCH_JFR` benchmarks the real recordings.

`workflow_dispatch` only works for workflows that already exist on the default branch, so to
benchmark a branch that has not been merged yet, push it as `bench/<something>` - the workflow also
triggers on any `bench/**` branch.

## Module-specific Commands
```bash
# Build only the parser core module
./gradlew :parser-core:build

# Build only the demo
./gradlew :demo:build

# Run the demo application directly
./gradlew :demo:run --args="jafar /path/to/recording.jfr"
```
